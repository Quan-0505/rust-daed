# Rust daed 3.2.0 — pinned upstream update

The UI is DaedNext `dc4af0e4d9e855e0d6ba6d719a2cc70f0be64327`. Compared with the previous build's `ae83c280f6b5`, it adds seven commits, including production feature validation, dashboard 3.2.0, overview/chart and LSP caching, and bounded log-query retries with explicit query errors and isolated filtered results.

The engine is DaeNext `f40c3494c7769efd796afff671d459db78f7ace9`, 53 commits after the previous build's `1fe97979b6f8`. Changes include DNS actor/flight cleanup, subscription cancellation and pending persistence, retained log worker identity, derived TLS cache invalidation, Meek recycling guards, Salamander socket GRO handling, QUIC receive/idle bounds and UDP/VLESS buffer reuse.

The existing sticky-ip patch applies to this exact revision. Its SHA256 is recorded in `upstream.json`; preparation verifies the patch and independent sticky module source before building. Upstream production default features are retained, including native Aya/eBPF, jemalloc and BoringSSL. AWS-LC and Rustls are not claimed as production providers.

Release builds use static CRT, two build jobs, one codegen unit and LTO disabled to fit the build host. CPU baselines are separately compiled as x86-64-v2, x86-64-v3 and generic ARM64. The frontend is shipped under `/usr/share/daed/web`, not replaced by this repository's development mock UI.

APK v2 is a source/archive format. Canonical OpenWrt 25.12 assets are converted by its SDK to actual ADB/APK v3 and compared against the original program, Geo data and web files. The old script that merely renamed tar archives as v3 is superseded by `build-release.sh` and `package-release.py`.

Validation results are recorded after completion. Only public upstream sources and public geodata are included; no production account or device state is used.
